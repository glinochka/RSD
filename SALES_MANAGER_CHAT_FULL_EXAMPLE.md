# Sales Manager: сквозной пример чата с полными LLM-промптами

Ниже разобран фактический workflow шаблона `sales_manager` по текущему коду, в формате одного реального сценария: что получил агент, какие function-calls были вызваны, что именно ушло в LLM и какой ответ вернулся.

## 1) Исходные данные сценария

- Канал: `telegram_userbot`
- `template_type`: `sales_manager`
- Режим: `draft_only`
- `min_confidence`: `0.75`
- `confirmation_policy`: `never_confirm`
- `allowed_tools`: `["schedule_dm", "skip_lead", "record_lead_signal"]`
- `knowledge_scope_id`: `101`
- `agent_id`: `77`
- `user_external_id`: `12345`
- Входящее сообщение:
  - `Ищем подрядчика для AI-автоматизации отдела продаж, есть кейсы?`

Пример базового системного промпта агента (`prompt`), который хранится у агента и прокидывается в runtime:

```text
Ты sales-агент B2B. Работаешь вежливо, кратко и по делу.
Твоя цель — квалифицировать интерес и довести до следующего шага (диагностика/демо/передача ЛПР).
Не обещай того, чего нет в контексте.
```

Пример части `template_config`, которая участвует в промптах:

```json
{
  "mode": "draft_only",
  "min_confidence": 0.75,
  "confirmation_policy": "never_confirm",
  "allowed_tools": ["schedule_dm", "skip_lead", "record_lead_signal"],
  "sales_product_name": "AI-автоматизация продаж",
  "sales_offer_type": "SaaS + внедрение под ключ",
  "sales_usp": "Запуск за 5 минут, интеграция с CRM, аналитика диалогов в одном окне",
  "enable_chat_portrait": true,
  "generation_model": "deepseek-chat",
  "qualification_model": "deepseek-chat"
}
```

---

## 2) Что делает агент по шагам

### Шаг 0. `MessageProcessor.process()`

1. Логирует входящее сообщение как `role=user`.
2. Обновляет портрет чата (`update_chat_portrait`) — LLM вызов.
3. Запускает `TemplateRuntimeService.execute(..., template_type="sales_manager")`.
4. После выполнения логирует:
   - tool events как `role=operator`
   - финальный ответ как `role=agent`

---

## 3) LLM вызов #0: обновление портрета чата (`update_chat_portrait`)

### Что ушло в LLM

**model:** `deepseek-chat`  
**temperature:** `0.1`

**system (полный):**

```text
Ты sales-агент B2B. Работаешь вежливо, кратко и по делу.
Твоя цель — квалифицировать интерес и довести до следующего шага (диагностика/демо/передача ЛПР).
Не обещай того, чего нет в контексте.

Ты модуль памяти клиента. Обнови портрет клиента/чата на основе нового сообщения. Портрет должен быть кратким, фактическим и полезным для будущих ответов ассистента. Включай: цели, интересы, ограничения, предпочтительный стиль общения, важные факты и текущий контекст. Не выдумывай данные, не добавляй markdown, верни только итоговый портрет.
```

**user (полный):**

```text
Текущий портрет:
Портрет пока отсутствует.

Новое сообщение клиента:
Ищем подрядчика для AI-автоматизации отдела продаж, есть кейсы?

Верни обновлённый портрет (до 2000 символов).
```

### Что предположительно вернул LLM

```text
B2B-клиент с запросом на подрядчика по AI-автоматизации продаж. Интересуется практическими кейсами и подтверждением экспертизы. Предпочитает конкретику и прикладной формат ответа.
```

Этот текст сохраняется как `chat_portrait` и подмешивается в следующие промпты.

## 4) LLM вызов #1: квалификация лида через FC (`qualify_message`)

На этом этапе runtime:
- поднимает/проверяет FSM контакт (`DISCOVERED`);
- передает текущую стадию, портрет и недавнюю историю в классификатор.

### Что ушло в LLM

**model:** `deepseek-chat`  
**temperature:** `0.1`  
**tool_choice:** `auto`  
**tools:** `engage_lead`, `ignore_lead`

**system (полный):**

```text
Ты sales-агент B2B. Работаешь вежливо, кратко и по делу.
Твоя цель — квалифицировать интерес и довести до следующего шага (диагностика/демо/передача ЛПР).
Не обещай того, чего нет в контексте.

Ты модуль pre-sales скрининга с function-calling. Продукт: AI-автоматизация продаж. Категория: SaaS + внедрение под ключ. Твоя задача: понять, стоит ли писать человеку в личку и как вести следующий шаг продаж.
Выбирай ровно один function call:
1) engage_lead - если нужно продолжать диалог/продажу.
2) ignore_lead - если лид нецелевой или писать не нужно.
Стадия продажи: DISCOVERED.
Учитывай этап воронки, контекст и историю взаимодействия.

Портрет текущего клиента/чата:
B2B-клиент с запросом на подрядчика по AI-автоматизации продаж. Интересуется практическими кейсами и подтверждением экспертизы. Предпочитает конкретику и прикладной формат ответа.

Ключевое УТП:
Запуск за 5 минут, интеграция с CRM, аналитика диалогов в одном окне
```

**user (полный):**

```text
Вот сообщение из чата потенциального клиента:
Ищем подрядчика для AI-автоматизации отдела продаж, есть кейсы?

Реши, стоит ли отписывать этому человеку в личку для продажи.
```

### Какой FC вызвал LLM (предположительно)

```json
{
  "name": "engage_lead",
  "arguments": {
    "intent": "target_hot",
    "confidence": 0.93,
    "reason": "пользователь явно ищет подрядчика и просит кейсы",
    "lead_temperature": "hot",
    "stage_hint": "first_touch",
    "handoff_ready": false
  }
}
```

### Что сделал агент после FC

- Принял решение `decision=engage`, confidence выше порога.
- Перевел FSM: `DISCOVERED -> QUALIFIED`.

## 7) LLM вызов #3: выбор действия через tools (`_execute_sales_tools`)

Здесь модель должна не писать обычный текст, а выбрать tool call.

### Что ушло в LLM

**model:** `deepseek-chat`  
**temperature:** `0.2`  
**tool_choice:** `auto`  
**tools:** из `SalesToolRegistry` (в этом примере доступны `schedule_dm`, `skip_lead`, `record_lead_signal`)

**system (полный):**

```text
Ты sales-агент B2B. Работаешь вежливо, кратко и по делу.
Твоя цель — квалифицировать интерес и довести до следующего шага (диагностика/демо/передача ЛПР).
Не обещай того, чего нет в контексте.

Ты управляешь действиями sales-агента через function tools. Не пиши свободный ответ вместо действия, выбери tool call. Если лид нецелевой — используй skip_lead.

Портрет текущего клиента/чата:
B2B-клиент с запросом на подрядчика по AI-автоматизации продаж. Интересуется практическими кейсами и подтверждением экспертизы. Предпочитает конкретику и прикладной формат ответа.
```

**user (полный):**

```text
Классификация: {"decision":"engage","intent":"target_hot","confidence":0.93,"reason":"пользователь явно ищет подрядчика и просит кейсы","lead_temperature":"hot","stage_hint":"first_touch","handoff_ready":false}
Черновик outreach: Здравствуйте! Увидел ваше сообщение в чате про AI-автоматизацию продаж. Если хотите, отправлю 2-3 релевантных кейса с цифрами и коротко покажу, как это обычно встраивается в CRM без долгого запуска.
Канал: telegram_userbot
```

### Какой FC вызвал LLM (предположительно)

```json
{
  "name": "schedule_dm",
  "arguments": {
    "text": "Здравствуйте! Увидел ваше сообщение в чате про AI-автоматизацию продаж. Если хотите, отправлю 2-3 релевантных кейса с цифрами и коротко покажу, как это обычно встраивается в CRM без долгого запуска.",
    "target_user_external_id": "12345"
  }
}
```

### Что вернул локальный tool execution

`SalesToolRegistry.execute_tool("schedule_dm", ...)`:
- валидирует schema аргументов,
- проверяет confirmation policy,
- проверяет idempotency,
- кладет сообщение в `agent_sales_dm_queue`.

Предположительный `tool_result`:

```json
{
  "ok": true,
  "tool_name": "schedule_dm",
  "tool_args_hash": "sha256(...)",
  "tool_status": "draft_requires_review",
  "latency_ms": 27,
  "idempotency_key": "sha256(...)",
  "result": {
    "queued": true,
    "status": "draft_requires_review",
    "payload": {
      "text": "Здравствуйте! Увидел ваше сообщение в чате про AI-автоматизацию продаж. Если хотите, отправлю 2-3 релевантных кейса с цифрами и коротко покажу, как это обычно встраивается в CRM без долгого запуска.",
      "target_user_external_id": "12345",
      "source_chat_id": null
    }
  }
}
```

## 8) Что в итоге ответил агент

Так как последний `tool_status = draft_requires_review`, runtime вернет:

```text
Требуется подтверждение владельца. Черновик:
Здравствуйте! Увидел ваше сообщение в чате про AI-автоматизацию продаж. Если хотите, отправлю 2-3 релевантных кейса с цифрами и коротко покажу, как это обычно встраивается в CRM без долгого запуска.
```

Также в аналитике появится `operator` событие по tool, а FSM получит переход:

- `QUALIFIED -> QUEUED`

## 9) Краткая карта FC в этом сценарии

1. `qualify_message` (LLM FC): `engage_lead(...)`
2. `_execute_sales_tools` (LLM FC): `schedule_dm(...)`
3. Локальный runtime ответ пользователю: статусный текст + черновик DM

Если нужно, могу сделать вторую версию этого же файла для ветки `ignore_lead` (нецелевой лид) и отдельно для `mode=auto` (где статус станет `sent_auto`).
