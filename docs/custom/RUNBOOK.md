# /custom — runbook оператора

Раздел `/custom` — это подсистема массовых автоматизаций в социальных сетях (пока Telegram). Она работает параллельно с обычными ИИ-агентами `/agents`.

## Архитектура в двух словах

- Админ создаёт **автоматизацию** и выдаёт клиенту логин/пароль.
- В автоматизацию загружается **пул Telegram-аккаунтов** (сессии).
- Аккаунты классифицируются: `one_day`, `mid`, `trusted`.
- Система вступает в чаты/каналы, ведёт нейрокомментинг, мониторит сообщения, перехватывает заявки и передаёт лиды.
- Все промпты, частоты и модули настраиваются в UI.

## Первый запуск

1. Скопируйте блок `/custom` из `.env.example` в корневой `.env`.
2. Заполните:
   - `CUSTOM_ADMIN_LOGIN`, `CUSTOM_ADMIN_PASSWORD_HASH` (bcrypt).
   - `CUSTOM_ADMIN_JWT_SECRET_KEY`, `CUSTOM_AUTOMATION_JWT_SECRET_KEY`.
   - `DEEPSEEK_API_KEY` (используется для всех LLM-выводов в `/custom`).
   - `TELEGRAM_USERBOT_API_ID` / `TELEGRAM_USERBOT_API_HASH` (желательно, иначе используется opentele).
3. Примените миграции: `alembic upgrade head`.
4. Засейте админа: `python -m backend.app.router_custom.admin_seed` (или `python -m app.router_custom.admin_seed` из папки `backend`).
5. Запустите backend. При старте автоматически стартует `CustomAutomationScheduler` — фоновые задачи per-автоматизация.

## Жизненный цикл автоматизации

### 1. Создание и доступ

- Админ: `/custom/admin/automations` → создать автоматизацию.
- Вкладка **Access** → создать логин/пароль для клиента.
- Клиент заходит через `/custom/login` и видит только свою автоматизацию.

### 2. Загрузка аккаунтов

- Клиент: `/custom/automations/:id/accounts`.
- Один аккаунт: QR-код (Telegram → Настройки → Устройства → Подключить устройство) или код по SMS. Если на аккаунте 2FA — пароль в том же блоке.
- Массово:
  - `.zip` с `.session` файлами.
  - Один `.session` файл.
  - `.csv` с колонками `phone_number`, `username`, `display_name`, `account_class`.
- После добавления `AccountHealthWorker` сам проверяет сессии и классифицирует аккаунты (аватар, bio, диалоги). Кнопка «Проверить» нужна только чтобы форсировать проверку сразу.
- Класс `trusted` система ставит сама по признакам аккаунта; вручную его можно поправить, но это не обязательно.

### 3. Чаты

- **Импорт**: загрузите `.csv`/`Excel` со списком ссылок/ID. Система создаст `ChatTarget` в статусе `pending`.
- **Автопоиск (Stage 6.5)**: `/custom/automations/:id/chats/discovery` → введите тему. Worker найдёт чаты через Telegram, отфильтрует LLM по релевантности, и либо сразу создаст чаты, либо покажет их для одобрения (если включена ручная модерация).
- **Вступление**: система сама вступает в чаты по расписанию, но можно нажать **Вступить** вручную. Обрабатываются `FloodWait` и retry.
- Если включены модули в настройках, они применяются ко всем вступившим чатам (кроме `inactive`). Режим чата больше не блокирует нейрокомментинг/обсуждения.

### 4. Лиды и передача

- Лиды создаются из:
  - Мониторинга чатов (сообщение похоже на заявку).
  - DMP.one (купленные контакты).
- Каждому лиду назначается аккаунт пула (`assigned_account_id`), который ведёт диалог. DMP-лиды с телефоном сначала резолвятся в Telegram через trusted-аккаунт (ImportContacts), как в ИИ МОП.
- **SEO SaaS**: квалифицированный лид не уходит в продажи — цель регистрация по UTM/промокоду. Если задан `conversion_check_url`, уже купивших пропускаем.
- **Фулфилмент**: после прогрева уведомление на Telegram МОПа (`lead_manager_contact`) и сделка в AmoCRM с комментарием-перепиской.
- **DMP-бот**: без ИИ-агентов. Идентифицированный лид из DMP уходит в Telegram-бота и добавляется строкой в Google Таблицу (1 лид = 1 ряд). Бот шлёт уведомления только после логина и пароля (те же, что «Доступ клиента»). Рейт-лимит: 5 неверных попыток → пауза 15 минут. Подписки хранятся в БД: после рестарта контейнера `/start` не нужен, webhook восстанавливается сам, недоставленные лиды досылаются.
- **Передача лида** в произвольном пайплайне:
  - Если `is_amocrm_enabled` и подключена интеграция — лид уходит в AmoCRM.
  - Если задан `lead_manager_contact` — уведомление менеджеру (можно вместе с AmoCRM).
- **DMP webhook:** URL из настроек решения: `POST /api/custom/webhooks/dmp/{automation_id}/{secret}`. В DMP One вставьте этот URL и включите JSON. Старый вариант с заголовком `X-DMP-Webhook-Secret` тоже работает. Параллельно работает polling заказов.


### 5. Промпты

- `/custom/automations/:id/prompts`.
- При создании автоматизации создаются default-шаблоны для всех типов. Для пайплайнов SEO SaaS и фулфилмент — отдельные системные промпты DMP и квалификации.
- Можно редактировать, тестировать, включать/выключать. Каждое сохранение создаёт новую версию.
- Поддерживаемые переменные подсвечиваются в UI.

### 6. Настройки и флаги

- `/custom/automations/:id/settings`.
- Включаются модули: перехват заявок, нейрокомментинг, шиллинг, искусственная активность в чатах, DMP.one, AmoCRM. При включении любого модуля статус сам становится `active`.
- Для SEO SaaS и фулфилмента в настройках: ссылка с UTM, промокод, URL проверки регистрации. У фулфилмента — Telegram МОПа.
- Три встроенных решения создаются миграцией / при старте планировщика: `seo-saas`, `fulfillment`, `dmp-bot`.
- У DMP-бота в настройках три блока: API-ключ Telegram-бота (webhook ставится сам), вебхук DMP.one, Google Таблица (ссылка/ID, лист, JSON сервисного аккаунта). Тумблер «Квалификация» по умолчанию выключен: если включить, лид сначала прогревается ИИ, и только квалифицированный уходит в бот и таблицу.
- Настраивается стратегия ротации (`round_robin`, `least_used`, `risk_weighted`) и дневной лимит сообщений на аккаунт.
- Система предупреждает, если для включённого модуля не хватает аккаунтов нужного класса.
- Дальше система работает автономно: вступление, мониторинг, комментинг, прогрев лидов и передача менеджеру/AmoCRM. Оператору остаётся подливать аккаунты и чаты.

## Фоновые задачи (scheduler)

При старте backend запускается `CustomAutomationScheduler`. Для каждой **active** автоматизации он держит циклы:

| Задача | Интервал (по умолчанию) | Что делает |
|--------|-------------------------|------------|
| `monitor` | 60 сек | Сканирует чаты, дедуплицирует сообщения, ищет заявки, отправляет ЛС от trusted-аккаунта. |
| `join` | 120 сек | Вступает в `pending` чаты. |
| `discovery` | 30 сек | Доигрывает pending-задачи автопоиска чатов. |
| `neurocommenting` | 300 сек | Пишет комментарии во все вступившие чаты (кроме `inactive`). |
| `discussion` | 240 сек | Отвечает в дискуссиях во всех вступивших чатах (кроме `inactive`). |
| `lead_warmup` | 90 сек | Читает ответы лидов в ЛС, продолжает диалог и сам передаёт квалифицированных. |
| `dmp_poll` | 300 сек | Опрашивает DMP.one по pending-заказам. |
| `amocrm_sync` | 600 сек | Синхронизирует статусы сделок AmoCRM. |
| `health` | 300 сек | Проверяет аккаунты пула на бан/сессию, классифицирует новые. |

Scheduler каждую минуту сверяет список активных автоматизаций с БД — новые подхватываются без перезапуска.

## Риски и защита

- **Баны**: при `FloodWait` — откладываем retry; при бане/дективации — помечаем `is_banned`, исключаем из ротации.
- **Дедупликация**: уникальный `dedup_key` на уровне БД, поэтому даже если 10 аккаунтов пула в одном чате, заявка обработана будет один раз.
- **Multi-tenancy**: все запросы фильтруются по `custom_automation_id`; клиент не видит чужие автоматизации.
- **Ручная модерация**: авто-поиск чатов может находить неподходящие каналы — рекомендуется включать `require_approval`.

## Проверка вручную (E2E checklist)

### SEO SaaS (без AmoCRM)

1. Создать автоматизацию, `industry=seo_sass`.
2. Загрузить 5-10 сессий, дождаться классификации.
3. В настройках указать `lead_manager_contact` (Telegram или email).
4. Загрузить Excel со списком чатов → нажать **Вступить**.
5. В одном из чатов написать заявку (например, "Кто делает SEO?").
6. Дождаться, пока `monitor` отработает (до 60 сек).
7. Проверить лиды — должен быть новый лид, и assigned-аккаунт должен написать в ЛС.
8. Нажать **Передать лид** — уведомление должно уйти на `lead_manager_contact`.

### Фулфилмент (с AmoCRM)

1. Включить AmoCRM в настройках, сохранить `client_id` / `client_secret` / поддомен, указать Redirect URI в карточке интеграции AmoCRM и нажать «Подключить».
2. Повторить шаги SEO SaaS.
3. При передаче лида он должен появиться в AmoCRM с `amocrm_lead_id`.

### DMP-бот (без ИИ)

1. Открыть решение `dmp-bot` → Настройки.
2. Выдать клиенту логин/пароль в «Доступ клиента».
3. Вставить API-ключ бота, JSON сервисного аккаунта Google и ссылку на таблицу. Выдать сервисному email права редактора.
4. Вебхук DMP скопировать в DMP One.
5. Написать боту логин, затем пароль.
6. Отправить тестовый JSON на вебхук DMP — в боте «Новый лид: …», в таблице новая строка.

### Авто-поиск чатов

1. В Discovery ввести тему "SEO оптимизация".
2. Дождаться статуса `awaiting_approval` (или `completed` если `require_approval=false`).
3. Одобрить найденные чаты → они появятся в списке чатов в статусе `pending`.
