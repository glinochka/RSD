## Проблема

Выбывший аккаунт оставался владельцем своего пула в задаче Телеграм УБТ. Отдать эти чаты другому аккаунту можно было только перемешав весь пул.

## Решение

В строке аккаунта пула кнопка «Заменить». Свободный аккаунт этой автоматизации, которого ещё нет в задаче, забирает те же чаты только в этой задаче. Уже собранный addlist переезжает на него тем же slug, без нового выпуска и без вступления в момент клика. Вход делает обычная волна `join_task_waves`. Перенесённые чаты закреплены: следующий тик не отдаёт их соседу, который уже сидит в той же папке кабинета. «Перемешать» закрепку снимает.

## Что сделали

`POST /api/custom/automations/{id}/task-pool/replace` переписывает `account_ids`, assignments и строку addlist этой задачи, обновляет живую джобу и ставит новому аккаунту actor-membership без `JOINED`. `filter_id` старого диалогового фильтра на нового не копируется. Слот старого на чатах только этой задачи удаляется, статус `LEFT` не ставится, выход из Telegram не вызывается. Пока на чате есть занятый слот, `ensure_watcher` не сажает второго вотчера.

## Что сознательно не делали

Не выбираем замену сами, не меняем другие задачи, не собираем новый addlist и не ускоряем волну, паузы и капы. Старого аккаунта из каналов не выводим. Обычный захват папки для задач без замены не переписывали. Парсер и подготовка аккаунта по-прежнему считают занятым только слот с ролью вотчера.
